# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

EVA-UI is a personal UI study: recreations of Neon Genesis Evangelion style screens in HTML and CSS, with vanilla JavaScript added where a screen needs to be interactive. Each study lives in its own folder holding an `index.html` and a `style.css`, plus a `script.js` once it has behavior. Folder names are a letter for the type of screen plus a number: `W-1` is the first Warning screen and `C-1` is the first Countdown screen. Pick a new letter to fit the screen type rather than assuming `W`. `M-1` is the MAGI study: `data-state` on the stage and `data-status`/`data-vote` on each plate drive it, with the deliberation timers in `script.js`. It is planned as the first with WebGL (a canvas behind the DOM, with all text and state staying in HTML). Its `references/` folder holds reference images and is gitignored. There is no build step, package manager, linter or test suite. Do not add any without asking. `W-1` was built CSS only; `C-1` is the first study with a `script.js`.

## Running a study

Open `<study>/index.html` (for example `W-1/index.html`) directly in a browser. Fonts load from Google Fonts, so a network connection is needed for the intended look. To screenshot or measure the rendered page, serve the folder (`python3 -m http.server` from the repo root) rather than relying on reading the CSS.

## Conventions that hold across studies

- **Each study is self-contained.** Its own `index.html`, `style.css` and `script.js`, no shared stylesheet or shared script. Copying a folder to start the next study is the intended workflow.
- **The stylesheet is a teaching document.** It is ordered top to bottom as variables, layout, type, graphics, motion, with numbered section headers and comments explaining why each technique is used. Keep that order and keep the comments when editing. Add new rules to the matching section.
- **Palette lives in `:root` variables** (`--accent`, `--ink`, `--bg`, plus the three `--font-*` families). Change colors there, not on individual rules.
- **Fixed-size stage.** W-1 is a 1280x720 `.screen` with `overflow: hidden`, and everything inside is positioned relative to it. It is deliberately not responsive. C-1 centers its stage with `display: grid` on `body` and `margin: auto` on `.screen`, and `script.js` publishes a `--scale` custom property that `.screen` applies with `zoom` (not `transform`, so the layout size shrinks too). The fit leaves a 48px margin (12px on narrow windows) so the registration marks drawn on the `body` background stay visible around the stage. Portrait phones under 600px wide get a rotate prompt instead, since the page cannot lock orientation. The scale is measured from `documentElement.clientWidth`/`clientHeight` and the viewport meta carries `minimum-scale=1`; without both, a mobile browser widens the layout viewport to the 1280px stage and the fit and the 600px rotate query both misread the screen. The `sweep` keyframe hardcodes `720px`, so changing the screen height means changing that too.
- **CSS owns the look, JS owns the behavior.** Looping motion stays in CSS (`@keyframes` with `steps()` for hard blinks). JavaScript handles state and interaction, and drives the look by toggling classes, `data-*` attributes or CSS custom properties, never by writing inline styles. Keep it plain vanilla JS in a `script.js` loaded with `defer`, with no libraries, bundler or build step.
- **C-1 is the model for the split.** Each seven-segment digit is a `.digit` with a `data-v` attribute (0 to 9), and a single CSS table maps each value to its lit segments, so `script.js` never touches individual segments. `data-state` on `.screen` (`idle`, `running`, `done`) drives the power-source swap (INTERNAL from the moment the countdown starts, back to EXTERNAL on reset) and the whole end-of-countdown alert (red backdrop, warning label, hazard bands, red digits). Those pieces sit in the markup from the start and `done` just reveals them, so the alert animations stay in CSS. `aria-current` on a mode label drives its highlight. The end-of-countdown alarm is `C-1/sounds/alarm.mp3`, played twice with a 500ms gap by `script.js`; START unlocks audio with a muted play because browsers need a gesture first, and leaving the done state cuts it off. The countdown measures time against a fixed end timestamp each frame, not by accumulating ticks. The controls row is `hidden` in the HTML until the script runs.
- **Reduced motion applies to both.** Every CSS animation class is switched off or paused under `prefers-reduced-motion`, and a new one must be added to that media query. JS that animates or auto-updates should check `matchMedia('(prefers-reduced-motion: reduce)')` and fall back to a static state.
- **Studies degrade without JS where practical.** Start from the working CSS-only version and layer behavior on top, so the page still shows something sensible if the script fails.
- **Japanese text** carries `lang="ja"`. Letter-spaced text needs a matching `padding-left` to stay optically centered (see `.title-en`).
- **SVG parts are styled with `stroke` and `fill`**, not `border` and `background` (see `.hex`).
